# /handoff-package — クライアント移管ZIPの作成（フェーズ2）

`league-domain-migration-guide.html` のフェーズ2（ローカルにファイル一式を書き出す）を自動化するスキル。
**このスキルが行うのはZIPを作るところまで。** メール送付（フェーズ3）や、GitHubアカウント作成・公開設定はクライアント側の作業であり、Leagueも本スキルも行わない。

引数 `$ARGUMENTS`: 対象ページのファイル名（例: `ykn.html` または `ykn`）。`sites/` プレフィックスは付けても付けなくてもよい。省略された場合はユーザーに聞く。

---

## 手順

### 1. 入力の正規化とリポジトリルートの特定

- `$ARGUMENTS` の先頭トークンから `sites/` プレフィックスと `.html` 拡張子を取り除き、会社スラッグ（例: `ykn`）を得る。
- `git rev-parse --show-toplevel` でリポジトリルートを確定する（このスキルを呼んだ場所がサブディレクトリでも安全に動くように）。
- ルート直下に `sites/`・`images/`・`logos/` があることを確認する。`sites/` が存在しない、または `sites/<slug>.html` が無い場合は、`Glob` で `sites/*.html` を一覧し、候補を挙げてユーザーに確認する。ここで止まる。

### 2. 作業フォルダを用意する

- 出力先は既定で `~/Downloads/<slug>-handoff`（Windowsなら `$env:USERPROFILE\Downloads\<slug>-handoff`）。第2引数でユーザーが別の場所を指定していればそれを使う。
- 既に同名フォルダが存在し中身がある場合は、上書きしてよいかユーザーに確認してから進める（無言で消さない）。
- フォルダ（と直下に `images/`・`logos/`）を作成する。

### 3. ページ本体をコピーして `index.html` にする

- `sites/<slug>.html` の中身を作業フォルダ直下に **`index.html`** という名前で保存する。
- これは元の `sites/` フォルダのような1階層下ではなく、作業フォルダの直下に置かれる点が重要（次のパス補正の理由になる）。

### 4. 実際に使われているローカル画像だけを特定してコピーする

- コピーした `index.html` の中身を読み、`../images/...` および `../logos/...` という相対パス参照を（`src=`, `href=`, `url(...)` などから）すべて拾い出す。`Grep` で `\.\./(images|logos)/[^"'\)]+` のようなパターンを使うと洗い出しやすい。
- **絶対URL（`http://`・`https://`）で参照されている画像（Google Drive由来の会社ロゴ・代表者写真・Topの背景など）はコピー対象外**。触らない。
- 拾い出した各パスについて、リポジトリ直下の `images/<file>`・`logos/<file>` が実在するか確認する。実在すれば作業フォルダの `images/`・`logos/` に同名でコピーする（サブパスがあればディレクトリ構造も保つ）。実在しない場合は壊れた参照として警告リストに残し、作業は止めずに続行する。
- **他クライアントのファイルを混ぜない**：ここでコピーするのは、このページが実際に参照しているファイルだけ。`images/`・`logos/` フォルダを丸ごとコピーしない。

### 5. 画像パスの `../` を外す

- 作業フォルダの `index.html` 内にある `../images/` と `../logos/` を、それぞれ `images/` と `logos/`（`../` を外した形）に一括置換する。それ以外の `../` や絶対URLには触れない。
- これは以前の不具合（`sites/` フォルダ内では逆に `../images/...` が必要だった件）の**逆方向**の補正であり、間違えると画像が消える。置換前後で `../images/` や `../logos/` が index.html 内に残っていないことを確認する。

### 6. 機械的な整合性チェック（人の目視確認の代わりにはならない）

- 補正後の `index.html` を再スキャンし、`images/`・`logos/` を参照している箇所ごとに、作業フォルダ内に対応するファイルが実在するかを確認する。欠けていればレポートする。
- 可能であれば `Start-Process` （PowerShell）または `start`（bash経由）で作業フォルダの `index.html` を既定のブラウザで開き、**ユーザー自身に見た目の崩れがないか目視確認してもらう**よう促す。ここで崩れているとクライアントに渡した後の切り分けが難しくなるため、必ず一言案内すること。

### 7. ZIPに圧縮する

- 作業フォルダ（`index.html` + `images/` + `logos/`）ごと ZIP に圧縮する。例（PowerShell）:
  ```powershell
  Compress-Archive -Path "<work>\*" -DestinationPath "<work>.zip" -Force
  ```
- 完成したZIPのフルパスをユーザーに報告する。

### 8. 最後の報告

- 出力ZIPのパス、コピーした画像/ロゴの一覧、壊れていた参照（あれば）を簡潔に報告する。
- 「ここから先（メール送付＝フェーズ3、GitHubアカウント作成・公開方法の選択はクライアント側）」であることを一言添え、メール送信などは行わない。

---

## 注意点（ガイドより）

- **パスの向きを逆に間違えない**：`sites/` 配下では `../images/...`、書き出し後の直下では `images/...`。毎回どちら向きか意識する。
- **他クライアントのファイルを混ぜない**：ZIPに圧縮する前に、参照されていないファイルが作業フォルダに紛れていないか確認する。
- GitHubリポジトリやアカウントは一切作成しない。すべてローカルの作業で完結する。
