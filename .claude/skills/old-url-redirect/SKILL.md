# /old-url-redirect — 旧URLの案内ページ設置（フェーズ4）

`league-domain-migration-guide.html` のフェーズ4（旧URLからのご案内・社内の後片付け）を自動化するスキル。
フェーズ2（`handoff-package`）でZIPを作成し、クライアントが実際に新しいURLで公開を終えている前提で実行する。**まだ移管が完了していない／新URLが未確定の場合はこのスキルを実行しない。**

引数 `$ARGUMENTS`: 「対象ページのファイル名（例: `ykn.html` または `ykn`）」＋「移管後の新URL（例: `https://ykn.example.com/`）」の2つ。どちらか欠けていればユーザーに確認する。

---

## 手順

### 1. 入力の確認

- 第1トークンから `sites/` プレフィックスと `.html` 拡張子を取り除き、会社スラッグを得る。
- 新URLは `http://` または `https://` で始まる絶対URLであることを確認する。そうでなければユーザーに確認する。
- `git rev-parse --show-toplevel` でリポジトリルートを特定し、`sites/<slug>.html` を対象ファイルとする。

### 2. 対象ファイルの現状確認

- `sites/<slug>.html` が存在しない場合、パスが正しいかユーザーに確認する（新規に作る想定ではない）。
- 中身を読み、既にリダイレクトページ（`meta http-equiv="refresh"` を含む）になっていないか確認する。既になっている場合は、URLが今回指定されたものと同じか比較し、違えば更新してよいかユーザーに確認する。

### 3. 旧URLページをリダイレクトページに置き換える

- `sites/<slug>.html` の中身を、以下のテンプレートの `新しいURLをここに` を実際の新URLに置き換えたもので**丸ごと上書き**する（`Write`または`Edit`で全置換。3箇所すべてを同じURLで揃える）。

```html
<!doctype html>
<html lang="en">
<head>
<meta charset="utf-8">
<meta http-equiv="refresh" content="0; url=https://新しいURLをここに">
<link rel="canonical" href="https://新しいURLをここに">
<title>Moved</title>
</head>
<body>
<p>This page has moved to <a href="https://新しいURLをここに">https://新しいURLをここに</a>.</p>
</body>
</html>
```

- 置き換え後、`git diff -- sites/<slug>.html` で差分をユーザーに見せる。

### 4. コミット・プッシュはユーザー確認の上で

- ファイルの上書きまでは実行してよいが、**コミットするかどうかは必ずユーザーに確認する**（このリポジトリは複数クライアントの共有リポジトリであり、変更は実際の公開ページに影響するため）。
- コミットする場合も、**プッシュは別途明示的な許可を得てから**行う。無断でpushしない。

### 5. 残りの後片付けはリマインドのみ（自動実行しない）

フェーズ4には他に、コード変更を伴わない社内作業が含まれる。これらは自動化せず、やることをリマインドするだけに留める：

- 社内の案件管理シート・過去のSlack投稿・提案資料などに旧URLの記載が残っていないか確認し、可能な範囲で新URLに更新する。
- 必要なら「旧URLの文字列を社内の他リポジトリ／ドキュメントで検索してほしいか」をユーザーに聞き、頼まれた場合のみ `Grep`/`WebFetch` 等で調査を手伝う（自発的に外部システムへ書き込みには行かない）。

### 6. 最後の報告

- 更新したファイルパス、設定した新URL、コミット/プッシュの有無を簡潔に報告する。
- チェックリスト（ガイドのフェーズ5相当）を参考に、残タスクがあれば一言添える：社内記録の更新、クライアントへの完了報告。
