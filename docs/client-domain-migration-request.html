ホームページの自己管理への移管に関するお願い

現在公開しております貴社の英語ホームページについて、「今後は貴社側で管理したい」というご希望に対応できるようになりました。まずLeagueより、ページのデータ一式をZIPファイルにまとめてチャットでお送りします。事前にアカウントなどをご準備いただく必要はありません。データをお受け取りいただいたあと、実際にどう公開するかを3つの選択肢の中からお選びいただき、貴社にて設定を行っていただく流れになります。公開が完了しましたら、新しいURLをLeagueまでチャットでお知らせください。

全体の流れ

大きく3段階に分かれます。ステップ1はLeagueが行い、ステップ2は貴社にて3つの選択肢からお選びいただき実施、ステップ3で公開完了のご連絡をいただきます。

ステップ 1（League が対応）

ページのデータをZIPファイルでお渡しする

ページのデータ（HTMLファイルと画像一式）をまとめたZIPファイルを、チャットでお送りします。貴社側で事前にご準備いただくものは特にございません。

ステップ 2（貴社にて対応）

3つの公開方法から選んで設定する

データをお渡しした後、実際にどう公開するかは3つの選択肢があります。以後の更新・管理も含め、こちらは貴社側で行っていただく形になります（引き続きLeagueへのご相談も可能です）。

ステップ 3（貴社にて対応）

公開完了後、新しいURLをLeagueへご連絡いただく

選んだ方法で新しいページの公開が完了しましたら、そのURLをLeagueへチャットでお知らせください。これまでLeagueが公開していた旧ページを、新しいURLへ自動的にご案内するページに更新します。

選択肢URLの例費用難易度の目安
1：github.ioでそのまま公開お客様のユーザー名.github.io/…無料やさしい（設定1箇所）
2：GitHubに独自ドメインを設定www.貴社名.com などドメイン代（年間数百〜数千円）ふつう（ドメイン設定が必要）
3：他社サーバー（Xserverなど）へ移設www.貴社名.com などドメイン代＋サーバー代ややむずかしい（アップロード作業あり）

どれか1つに決めなければならないわけではなく、まず1（無料・最速）で公開しておき、あとから2や3に変更することも可能です。迷われる場合は、まず1をお試しいただくことをおすすめします。

1

データの受け取り（すべての選択肢に共通）

目安 5分

  1. Leagueからチャットで送られたZIPファイルをダウンロードしてください

    League担当者よりチャットでお送りするメッセージに、ページのデータ一式をまとめたZIPファイルが添付されています。ダウンロードして展開（解凍）してください。中には index.html というファイルと、images・logos という2つのフォルダが入っています。この時点でGitHubのアカウントなどをご用意いただく必要はありません。

  2. 展開したフォルダの中の index.html をダブルクリックして、表示をご確認ください

    お使いのブラウザ（Chrome、Safariなど）でページが開き、これまで公開されていたホームページと同じ内容が表示されれば問題ありません。インターネットに接続していなくても表示されます。

  3. どの公開方法にするか、ご検討ください

    まだお決まりでない場合は、上記の3つの選択肢を参考にご検討ください（あとから変更することも可能です）。選択肢1・2をお選びの場合はGitHubアカウントのご用意が、選択肢3をお選びの場合はお使いのサーバーへのアップロードが、それぞれの手順の中に含まれています。

ここまで完了すると

貴社のPC上にページのデータ一式が揃った状態になります。次のステップ2で、実際にどう公開するかを設定していただきます。

2-1

選択肢1：github.ioでそのまま公開する場合

目安 20分

  1. GitHubの無料アカウントを作成してください

    github.com にアクセスし、無料アカウントを作成してください（メールアドレスがあればどなたでも登録できます）。すでにお持ちの場合はこの手順は不要です。

  2. 新しいリポジトリを作成し、受け取ったファイルをアップロードしてください

    GitHubにログイン後、右上の「＋」→「New repository」から新しいリポジトリを作成します（リポジトリ名は下記コラムを参考に決めてください）。作成後、そのリポジトリの画面で「Add file」→「Upload files」を開き、受け取ったZIPを展開した中身（index.html・imagesフォルダ・logosフォルダ）をまとめてドラッグ&ドロップし、「Commit changes」で保存してください。

  3. GitHub Pagesを有効にしてください

    作成したリポジトリの画面上部「Settings」タブ →左メニューの「Pages」を開き、「Source」を「Deploy from a branch」、「Branch」を「main」／「/ (root)」に設定して保存してください。

  4. 数分待ってURLを確認してください

    画面に表示される https://お客様のユーザー名.github.io/リポジトリ名/ のようなURLが、数分後に公開URLになります（リポジトリ名を特別な形にされた場合は https://お客様のユーザー名.github.io/ のみになります）。

コラム：URLをできるだけシンプルにしたい場合 — 通常、公開URLは お客様のユーザー名.github.io/リポジトリ名/ のように、リポジトリ名の部分が付きます。もし「リポジトリ名の付かない、シンプルな お客様のユーザー名.github.io」にしたい場合は、リポジトリ作成時の名前を ユーザー名そのもの＋.github.io（例：ユーザー名が carrirare であれば carrirare.github.io）にしてください。この特別な名前のリポジトリは1アカウントにつき1つしか作れません。

完了です

費用をかけずに、すぐ公開できます。あとから選択肢2・3に切り替えることも可能です。公開できたら、次の「ステップ3」で新しいURLをLeagueへご連絡ください。

2-2

選択肢2：GitHubに独自ドメインを設定する場合

目安 15分＋反映待ち（最大24時間程度）

  1. 選択肢1の手順でGitHub Pagesを有効にしてください

    まだの場合は、上記「選択肢1」の手順を先に行ってください。

  2. 使いたいドメインをご準備ください

    すでにお持ちのドメインがあればそちらをお使いいただけます。まだお持ちでない場合は、「お名前.com」「ムームードメイン」などのドメイン取得サービスで、年間数百円〜数千円程度でご取得いただけます。

  3. GitHub側でカスタムドメインを登録してください

    リポジトリの「Settings」→「Pages」の「Custom domain」欄に、使いたいドメイン（例：www.貴社名.com）を入力して保存してください。

  4. ドメインの管理画面でDNSレコードを追加してください

    ドメインの種類例設定するレコード
    サブドメイン（推奨）www.貴社名.comCNAMEレコードを1本、お客様のユーザー名.github.io 宛てに追加
    ルート（apex）ドメイン貴社名.comAレコードを4本、185.199.108.153／185.199.109.153／185.199.110.153／185.199.111.153 宛てに追加

    ドメイン取得サービスの管理画面にある「DNS設定」または「ネームサーバー設定」といった項目から追加できます（サービスによって呼び方が異なります）。

  5. 反映を待ち、HTTPSを有効にしてください

    GitHubの「Settings」→「Pages」画面で「DNS check successful」という緑のチェックが表示されたら（数分〜最大24時間程度）、同じ画面の「Enforce HTTPS」にチェックを入れてください。無料のSSL証明書が自動発行されます。

完了です

独自ドメインで、鍵マーク（HTTPS）付きのページが公開されます。設定でご不明な点があれば、Leagueまでお気軽にご相談ください。公開できたら、次の「ステップ3」で新しいURLをLeagueへご連絡ください。

2-3

選択肢3：他社サーバー（Xserverなど）へ移設する場合

目安 15〜20分

  1. GitHubは不要です

    この選択肢はGitHubを使いません。ステップ1で受け取り、展開（解凍）済みのファイル一式（index.html・imagesフォルダ・logosフォルダ）をそのままお使いください。

  2. お使いのサーバーにファイルをアップロードしてください

    Xserverなど、すでにお使いのレンタルサーバーがあれば、そのサーバーのファイル管理画面（ファイルマネージャー）またはFTPソフトを使って、フォルダ構成を保ったまま公開用フォルダ（public_html など、サーバーによって名称が異なります）にアップロードしてください。データベースやプログラムを使わない、そのまま表示できるシンプルなファイルのみで構成されているため、特別な設定は不要です。

  3. ドメインがそのサーバーを向くようにしてください

    すでにそのサーバーで別のサイトを運用されている場合は、ドメインの設定は完了しているはずです。新しくドメインを取得された場合は、契約されているサーバーの案内に沿って、ドメインの管理画面でネームサーバーまたはDNSの設定を行ってください（サーバー会社ごとに手順が異なるため、契約先のサポートページをご確認ください）。

この選択肢はサーバー会社ごとに操作画面が異なるため、本書では一般的な流れのみご案内しています。具体的な操作でご不明な点があれば、契約されているサーバー会社のサポート窓口にお問い合わせいただくのが確実です。

完了です

お使いのサーバー・独自ドメインでページが公開されます。公開できたら、次の「ステップ3」で新しいURLをLeagueへご連絡ください。

3

公開完了後、Leagueへ新しいURLをご連絡ください

目安 5分

  1. 新しいURLが確定したら、チャットでLeagueにお知らせください

    選択肢1・2・3のいずれかで新しいページの公開が完了しましたら、そのURL（例：https://お客様のユーザー名.github.io/リポジトリ名/ や独自ドメインのURL）をLeagueまでチャットでご連絡ください。

  2. Leagueにて旧ページを新URLへの案内ページに更新します

    ご連絡いただいたURLをもとに、これまでLeagueが公開していた旧ページを、新しいURLへ自動的にご案内するページに更新します。過去に共有された旧URLへのアクセスがあった場合も、迷わず新しいページにたどり着けるようになります。

ここまで完了すると

旧URLからも新しいページへ迷わずたどり着ける状態になり、移管作業がすべて完了します。

よくあるご質問

Q. 今のURL（github.io のもの）は使えなくなりますか？
旧URLへの直接のアクセスがあった場合も、ステップ3でご連絡いただいた新しいURLへ自動的にご案内するページに切り替えますので、過去に共有されたリンクが無効になることはありません。
Q. どの選択肢を選べばよいかわかりません。
まずは費用がかからず一番早い「選択肢1」で公開しておき、独自ドメインが必要になったタイミングで「選択肢2」に切り替える、という進め方がおすすめです。すでに他社サーバーやドメインをお持ちで、これまでの管理体制を変えたくない場合は「選択肢3」が向いています。迷われる場合はLeagueにご相談ください。
Q. GitHubのアカウントは必ず作らないといけませんか？
選択肢1・2（GitHubで公開する場合）をお選びのときのみ必要です。選択肢3（他社サーバーへ移設）をお選びの場合はGitHubは不要で、お受け取りいただいたZIPの中身をそのままお使いいただけます。
Q. 独自ドメインの取得や維持に費用はかかりますか？
ドメイン自体の取得・更新費用（年間数百〜数千円程度、ドメインの種類により異なります）は貴社のご負担となります。選択肢1・2のホスティング自体には費用はかかりません（選択肢3は別途サーバー費用が必要です）。
Q. ステップ2の設定は難しくありませんか？
選択肢1はGitHubアカウント作成を含め数十分程度で完了する簡単な設定です。選択肢2はさらにドメイン管理画面への値の追加が必要ですが、指定された値をコピー&ペーストしていただくだけです。選択肢3はご利用のサーバーによって操作が異なりますが、通常のファイルアップロードと同じ操作です。いずれもご不明な点があればLeagueにご相談いただけます。
Q. データを受け取ったあとのページの更新も、Leagueにお願いできますか？
恐れ入りますが、データをお渡しした後のページの更新は貴社にて行っていただく形になります。Leagueは今回のデータ引き渡し（ステップ1〜3）をもって、本ページの更新対応を終了いたします。選択肢1・2（GitHub）をお使いの場合はGitHub上でHTMLファイルを直接編集、選択肢3（他社サーバー）の場合はサーバー上のファイルを直接編集することでご更新いただけます。
ご不明点がございましたら、お気軽にLeague担当者までお問い合わせください。
